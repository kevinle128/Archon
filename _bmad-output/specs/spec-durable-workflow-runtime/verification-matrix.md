# Verification matrix

Durability is accepted through process-failure tests, not only unit tests around status transitions. Fixtures must be deterministic and must not depend on public provider networks in CI.

| Scenario                                                                                  | Required evidence                                                                                                                                                                                            |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `./scripts/deploy-pm2.sh` runs during a fake provider stream on the production PM2 layout | The API process identity changes, the active worker process identity and execution epoch do not, no second `node_started` appears, and the original run completes after the replacement API becomes healthy. |
| Replacement API reconnects to a worker started by the previous deployed build             | Observation remains truthful, compatible steering continues through the versioned contract, and incompatible mutations fail closed without stopping the worker.                                              |
| `./scripts/deploy-pm2.sh --reload-workflows` runs during an active workflow               | The PM2 app and worker identities remain unchanged and no reconnect or recovery transition occurs.                                                                                                           |
| API receives SIGTERM during an AI stream                                                  | The managed worker remains alive, no second `node_started` appears, the UI/API reconnects, and the original run reaches a valid terminal state.                                                              |
| API restarts with queued guidance                                                         | The same ordered queue is visible after reconnect and every accepted `message_id` is delivered or reconciled exactly once.                                                                                   |
| API restarts during `idle-after-interrupt`                                                | The worker retains the provider session, sub-state, queued guidance, and inactivity semantics; Stop does not become Cancel.                                                                                  |
| Worker exits before a provider checkpoint exists                                          | The run becomes recovery-required; no session id is guessed and no incomplete node is replayed automatically.                                                                                                |
| Worker exits after a checkpoint at a clean tool boundary                                  | Without an operator click, exactly one new epoch resumes the same provider session when confirmed, skips completed DAG nodes, and rejects writes from the old epoch.                                         |
| Worker exits after `tool_called` but before authoritative `tool_completed`                | Recovery blocks for an operator choice and issues no duplicate tool call on its own.                                                                                                                         |
| Heartbeat expires while the worker may still run                                          | No autonomous takeover, failure, cancellation, or abandonment occurs.                                                                                                                                        |
| API/supervisor restarts while the registered worker identity remains live                 | The exact worker is rediscovered; no replacement epoch or duplicate provider turn starts.                                                                                                                    |
| API/supervisor restarts without a host reboot                                             | The trusted host boot identity remains unchanged; an application restart cannot manufacture positive death evidence.                                                                                         |
| Supervisor records exit of the registered worker                                          | The durable exit evidence authorizes one automatic recovery attempt when the checkpoint is clean.                                                                                                            |
| Host reboots without a supervisor exit record                                             | A changed trusted boot identity proves the pre-boot worker is gone and authorizes one automatic recovery attempt when the checkpoint is clean.                                                               |
| PID is reused by a process with a different start token                                   | The old owner is classified as gone; the unrelated process is never treated as the workflow worker or signalled.                                                                                             |
| Exact-process probe is denied or unavailable                                              | Ownership remains ambiguous and no automatic takeover occurs, regardless of heartbeat age.                                                                                                                   |
| Two recovery coordinators race to claim the same run                                      | One atomic epoch claim succeeds; the loser starts no worker or provider turn.                                                                                                                                |
| Old worker writes after an accepted takeover                                              | Every stale-epoch execution/event/control mutation is rejected and cannot advance the run.                                                                                                                   |
| Strict provider recovery reports cold                                                     | No fresh substantive turn runs automatically; the outcome is `cold`, the operator sees degraded continuity, and uncertain work is not silently replayed.                                                     |
| Provider rejects or cannot verify resume                                                  | The outcome is `rejected`, `unsupported`, or `unverified`; it is never labelled restored.                                                                                                                    |
| API and worker run incompatible control versions                                          | Observation remains truthful; state-changing commands fail closed with a typed incompatibility result.                                                                                                       |
| Cross-provider session id is presented                                                    | Recovery rejects it before provider execution.                                                                                                                                                               |
| Original ENV/provider/user defaults changed after run start                               | Recovery uses the frozen run execution snapshot and original acting identity, not the new defaults.                                                                                                          |
| SQLite and PostgreSQL upgrade from a prior release                                        | Additive schema application succeeds, is idempotent, and yields equivalent recovery columns/indexes in both dialects.                                                                                        |
| Direct AI node, AI loop node, provider-calling loop group, and child workflow             | Each execution shape obeys the same owner, checkpoint, completed-node skip, and uncertain-effect rules.                                                                                                      |
| Pending approval or AskHuman state during API restart                                     | The durable gate remains pending and is neither auto-resumed nor terminalized by restart recovery.                                                                                                           |

## Test boundaries

- Provider adapters use conformance fakes that can emit an early session id, warm resume, cold fallback, rejection, and unverified resume.
- Process tests use real child processes and explicit readiness/exit signals; arbitrary sleeps and `last_activity_at` assertions are not death evidence.
- A production-layout acceptance test invokes the real PM2 deploy script with a deterministic fake provider. Environments without PM2 cover the same contract by restarting only the API process, but that does not replace the production-layout proof.
- At least one end-to-end browser test reconnects an Agent Node Room to a still-running worker and verifies that existing steering controls keep their inherited behavior.
- At least one adversarial test leaves an external-effect-shaped tool call without a result and proves that no automatic replay occurs.
