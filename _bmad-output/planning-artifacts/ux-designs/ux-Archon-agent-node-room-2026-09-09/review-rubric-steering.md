# Spine Pair Review (steering delta) — Archon

Scope: the live-agent-steering delta only. The transcript half was rubric-reviewed in September (`review-rubric.md`) and is not re-walked here except where the delta changed a statement that half owns.

Contrast figures marked _(computed here)_ were derived with the method `DESIGN.md:424` states — oklch → sRGB → relative luminance, from the two token files. The converter was calibrated first against four hexes the spine publishes (`node-bash`, `node-command`, `node-prompt`, `brand-magenta`) and reproduced all four exactly.

## Overall verdict

The mechanical delta is unusually clean — every `{token}` resolves, all eight steering components appear in both spines under identical names, all three new `sources:` paths and every new `file:line` citation verify against the tree. What is weak is the pair's accounting for its own claims and for the second spec: the delta added eight components and **zero rows** to the Measured contrast table, then asserted in `EXPERIENCE.md:242` that all but two dock pairings were "already measured in `DESIGN.md` Colors" — one of them, Legacy's send control, is not in that table and computes to **3.06:1**, a fail. Alongside that, the Key Flows capability-coverage line was never updated for the second spec, steering CAP-5 has no journey and a component rule that contradicts it, and five of DESIGN.md's eight canonical sections were left untouched while the frontmatter grew — three of them now carry sentences the dock falsifies.

The spine pair reads as one contract at the level a reader meets first (title, intro, IA, the interleaved tables) and as two documents stapled at the level a builder meets last (DESIGN.md's prose sections, the coverage line, Inspiration & Anti-patterns).

## 4. State coverage — thin

Walked the dock as an IA surface. Present and well handled: node running (`:169`), stop pressed / not acknowledged (`:170`), node stopped (`:171`), node resumed (`:173`), pending ask (`:174`), queue empty (`:175`), delivery failed (`:176`), no delivery echo (`:177`), connection lost with messages queued (`:178`), run paused by the stop (`:179`), and the race where the node finishes mid-stop (`:172`). The rubric's named checks are met except cold load and node finished.

### Findings

- **[high]** **No state for a steer aimed at a superseded attempt.** `SPEC.md:62` makes this a constraint — "A steer carries the node id and retry epoch it was written against. A steer aimed at a superseded attempt is rejected rather than delivered to a different run of the same node." The state is reachable in _this_ room and the spine describes reaching it: `EXPERIENCE.md:335` has the node opening node-scoped across two executions, and `NodeRoomHeader.tsx:64-76` lets the operator select one. An operator reading `Run 1` while `Run 2` runs has a dock with no defined behaviour, and the one outcome the spec names (rejection) has no surface. _Fix:_ a State Patterns row — either the dock is absent when the selected execution is not the live one, or the send is disabled with a reason in the manner of the pending-ask row.
- **[medium]** **"Node finished" has no dock row.** `:172` resolves the race by deferring to "its finished-node treatment", and that treatment is defined nowhere in the table — only in Open Questions (`:369`), as an assumption. The State Patterns table therefore points at a state it does not contain. _Fix:_ add the row carrying the assumed treatment (dock absent) and mark it as tracking the open question, so the table is self-contained.
- **[medium]** **No dock row for cold load.** `:139` covers the transcript only. Both controls "read the node's state" (`:127`) — before that state resolves, the dock has no defined rendering, and the two candidate answers (absent, or present-but-disabled) produce visibly different panels. _Fix:_ one row.
- **[medium]** **A stop that never lands has no exit.** `Stopping…` is disabled from the press "until the node acknowledges" (`:130`), the interface deliberately shows no countdown (`:170`), and the acknowledgement arrives on a poll that a dead or detached executor may never run. Nothing in the table returns the control. The engine's own rule against timer-driven mutation forbids auto-failing it — which makes the surfaced-state-plus-manual-action answer the required one, and it is missing. _Fix:_ a row for a stop unacknowledged past a stated bound: surface it, keep the run untouched, give the operator an action.
- **[medium]** **Queue scope is never stated as per-node.** `this tab only` appears three times (`:90`, `:178`, `:355`) and always about tab lifetime. `SPEC.md:62` stamps each steer with a node id, so the queue must be per-node — but `:192` says only that _row open/close_ state does not carry across nodes, and IA row `:51` is silent. The microcopy actively suggests the tab is the scope. _Fix:_ state it on the Draft box row and reflect it in the microcopy if the wording is now misleading.
- **[medium]** **Retry idempotency is unspecified.** `:132`/`:199` guard against double-pickup _from the box_; they say nothing about the stamped id. On an ambiguous failure (request timed out, delivery may have landed) a returned item re-sent with a fresh id produces either a duplicate delivery or two `sent` rows, and `:126` makes id the only correlation channel. _Fix:_ state that a returned item keeps its stamped id.
- **[low]** The connection-lost row (`:178`) covers the queue's survival but not whether **stop and send remain operable** while the stream is down. Pressing a control whose acknowledgement channel is dead is a different outcome from pressing it live.
- **[low]** The dock's presence rule is circular: "whenever the node can still receive a message" (`:50`) / "while the node can still receive a message" (`:127`), with no statement of which node types qualify. The same room serves `bash:`, `script:` and `approval:` nodes, which have no agent to steer.
