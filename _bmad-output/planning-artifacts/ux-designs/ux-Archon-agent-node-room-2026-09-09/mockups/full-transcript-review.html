4 · The two channels that carry state without colour

Status glyph — five characters for the five outcomes

✓succeeded ✕failed ◐running ⚠interrupted –unknown

Five different shapes, so a colour-blind reader loses nothing. – means unknown and nothing else: a missing output is a badge, never a glyph. ⚠ is its own character rather than a recoloured ✕ — an interrupted tool was stopped, not failed, and only Claude can produce it.

Family chip — hue plus a text channel that never depends on it

shell · code--node-bash
file · web--node-command
search · glob--node-prompt
todo · task--node-approval
generic--text-secondary

Siblings share a hue so the family palette stays quieter than the status colours. A reader who cannot separate the hues still gets the family from the chip's title, from the accessible name, and from the first word of the body bar — three text channels, so the colour is a scanning aid rather than a fact.

5 · Width pressure — what gives way, in order

▶✓Readpackages/web/src/experiments/console/components/inspect/ConsoleAgentHistoryList.tsx296 lines
▶✕shellcargo test -p gigo-harness-worker --test auto_retry rm02_4_2_tdd_us1_001exit 101

The panel is narrow on purpose. A path elides in the middle so the filename survives — a tail cut would have shown packages/web/src/experiments/console/com…, which identifies nothing. Commands and patterns elide at the end instead, where the front carries the meaning. Pressure is absorbed in a fixed order: chip cap, then headline elision, then badge priority — and a badge dropped here reappears in the body bar, so nothing is lost, only moved. The core hands the shell the complete string; the elision is the shell's, and the full path stays in the DOM for assistive technology and for copy.

6 · Who owns what — the line the two surfaces must not blur

Legacy and Console write their own JSX, so anything either one decides for itself is a place they can drift. This is the split the architecture spine fixes.

ThingOwnerWhy there
family, label, headlinecoreDeciding what a row means is one decision, made once. A shell never inspects a payload or a tool name.
status glyph charactercoreFive characters mapped from one outcome. Two shells each writing the map would diverge invisibly to sighted testing.
accessible name, body-bar textcoreRequired by the Accessibility Floor and named in no shared type until the spine added them.
badges, and their ordercoreArrives complete and ordered; a shell renders the array as given and never appends or reorders.
the inline diffcoreOne module computes hunks. Two callers would silently differ — the differ's context option defaults to 4.
occurrence groups and labelscoreHeaders appear only for two or more distinct occurrences; the label is composed once, never derived per shell.
collapsed / open defaultshellDOM state. Uncontrolled and seeded once — a controlled open would snap shut a row the reader opened.
manual open beats automaticshellAn explicit reader action outranks every rule and survives live re-renders.
the role="status" regionshellOne polite region for node transitions and failures — announcing every row of a fifty-row node is worse than silence.
stick-to-bottom, focusshellPins only while already at the bottom; an append never moves focus. Console ships this today, Legacy does not — the one place the surfaces are divergent right now.
where the checklist sitsshellRendered once, anchored at the last todo call.

Five shell-owned behaviours, enumerated deliberately: anything not on that list belongs to the core, and each of the five gets the same assertion in both surfaces' test files — which is what makes “both shells behave identically” checkable rather than aspirational.
