Run Archon implementation workflows from that root.


These files contain the Archon-owned slice of the current headless Workflow Commander plan.
They are written here so Archon agents can work locally without reading parent planning documents.
Archived folders and feature-scoped subfolders outside this directory are not active implementation input unless an Archon BMad workflow is explicitly changed to read them.

The Archon-owned scope includes Workflow Provider Binding, generic `provider` and `name` controller vocabulary, CLI JSON producer contracts, workflow run state, retry, resume, cancel behavior, workflow event production, non-blocking event outbox, delivery status, signed workflow event production, and Archon-side validation guidance.
The Archon-owned scope excludes Project Binding, BMAD mount, cwd enforcement from Hermes, BMAD invocation from Hermes, materialization, Project Work Items, Phase Tasks, HILT Gates, workflow event ingress, Story Status History, reconciliation, diagnostics, and Hermes user interaction.

The local contract package is `../../contracts/workflow-commander/`.
It contains the required local JSON schemas, examples, fixtures, and validator for the current handoff.
Producer stories may use those contracts only when the canonical validation command below passes as checked in.
If the validator fails, a required schema or example is missing, or a story needs a field that is not present in the validated package, that story is not implementation-ready.

Older Route Loop Routing UX artifacts are archived outside active planning discovery and must not be used as Workflow Commander input.

Readiness review should treat the UX scope control as satisfied when the active PRD, architecture, epics, and UX note all preserve the headless provider boundary.

Do not place Archon implementation artifacts in this planning folder.
