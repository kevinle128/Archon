Live Agent Steering

The read half of the node room already ships. This is the write half — and it is not “stop the node.” Two operations act on the live agent while the node keeps running: send it a message, and interrupt its current thinking to redirect it. Stopping the whole node already exists (Cancel); steering never touches the node lifecycle.

11 decisions2 parent spinesCAP-1..6status: final

The reframe

The provider already gives us the primitive. An interrupt ends the current turn but keeps the session alive — so the operator’s next message continues the same session. The elegant part: steering-interrupt and Cancel share the same low-level stream-abort; the only difference is what the executor does after. Cancel ends the node (existing path); steering keeps the node open and re-runs the same session. The one genuinely new engine behavior is that a steered node runs multiple turns on one live session instead of ending after the first.

What we are NOT doing — the superseded model

The prior design in this run modelled steering as a durable stop-and-resume: pause the run, persist a control marker, re-deliver on hydration. That conflated steering with Cancel and was ratified as over-engineering. It is gone — there is no durable steering state of any kind. These terms do not appear anywhere below except here:

The two operations

The single most important distinction. Both act while the node is running, but only one is in scope.

Cancel node

Existing · out of scope

The teardown / abort feature that already ships. Stops the whole node and the agent inside it; the node’s lifecycle ends.

  • Untouched by this feature.
  • Shown only as a separate dashed “already exists” path.
  • Governed by the HITL pause/resume invariants — see below.

Steer

New · this spine

Send a message to the running agent, and interrupt its current generation to redirect it — both without stopping the node.

  • Node stays running the whole time — a send or an interrupt never fails it (no pause, no pending, no resume).
  • Interrupt ends the current turn; the provider session stays alive.
  • Everything in-process / in-session; multi-turn on one session.
One shared abort primitive, two signals. The same stream-abort ends a turn either way — but Cancel aborts the one-shot node-level nodeAbortController (which fails the node at :3124), while steering aborts a fresh per-turn signal beside it, so the node-level :3124 check is never tripped by steering. operatorInterrupt names which signal fired; Cancel’s path is byte-for-byte unchanged (AD-2).

Inherited, read-only — and the line that anchors the distinction: the pause/resume HITL invariants do NOT apply to steering. HITL/AD-1 & AD-2 (pause-without-approval + resume CAS) and HITL/AD-6 (resumeInteractions) govern the Cancel / Ask lifecycle. Steering does not pause, does not resume, and does not reuse resumeInteractions. What steering does inherit: HITL/AD-3 (executor is sole appender, store assigns seq), HITL/AD-7 (split typed routes, server-side authorization), HITL/AD-8 (additive schema, both dialects), and Track A/AD-1, AD-2, AD-3, AD-10 (one core / two shells; the Console lint boundary).

Dependency direction

Each layer may depend only downward.

Adds no new port and no durable store: it drives the provider’s native interrupt + streaming-input on the live session handle held in the registry.

The in-session flow

The node never leaves running. Its agent moves between the two projected sub-states (AD-9). Cancel is a separate dashed teardown.

An interrupted turn never completes the node (AD-4): its partial output is not validated. The node completes only when a turn ends naturally with nothing queued.

Decisions

Eleven ADs. No “gate fix” cards — the durable model they patched is gone. Two cards carry the only genuinely new code: AD-4 (multi-turn on one session) and AD-2 (the one seam — a fresh per-turn abort signal beside Cancel’s one-shot node-level controller, with operatorInterrupt naming which fired).

Lifecycle & interrupt

AD-1

Steering acts on the live agent, never on the node lifecycle

Binds
CAP-1, CAP-2, CAP-3, CAP-5; the executor; the registry.
Prevents
modelling steering as a run pause / node stop (that is Cancel, which already exists); any durable stop-and-resume state.
Rule
Send and interrupt both operate on the live provider session of the running node. The node stays running throughout — no pause, no pending, no resume; a send or an interrupt never fails the node. (The one way a steered node ends in failure is the operator abandoning an interrupted node past its idle bound — AD-4 — the operator’s absence, not a steering act.) Stopping the whole node is the existing Cancel / abort path: out of scope, untouched. Steering only exists where there is a live agent session to act on.
AD-2the one seam

Interrupt is the provider’s own primitive (or a stream-abort); it ends the turn, not the session

Binds
CAP-2, IAgentProvider, the adapters, the executor’s abort seam.
Prevents
an engine-side kill; a bespoke steer channel; conflating interrupt with Cancel’s teardown; a steering abort falling through to node_failed.
Rule
Ending the agent’s thinking ends the current turn and leaves the session alive. Claude uses the SDK-native interrupt() (= query.interrupt()); a provider with no native keep-alive interrupt uses a stream-abort — codex re-runs the resumed thread (codex.resumeThread(sessionId), providers/src/codex/provider.ts:1006). The session, not a durable marker, carries continuity.
The abort seam
The executor’s nodeAbortController (dag-executor.ts:2209, created once per node, one-shot) is Cancel’s, and steering leaves it byte-for-byte untouched: it feeds sendQuery (:2223), the idle-timeout and cancel-poll abort it (:2298/:2325), the re-ask loop stops on it (:3032), and the inline :3124 check fails the node on it. Steering must not abort that controller — one-shot means a steering abort would kill turn N+1’s sendQuery and block multi-turn. Instead steering interrupts through a fresh per-turn signal: sendQuery receives the combination AbortSignal.any([nodeAbortController.signal, perTurnSignal]), so Cancel (node-level) or a steering interrupt (per-turn) both end the current turn — but each new turn gets a fresh per-turn signal while the node-level controller persists, which is what lets a node run more than one turn. The registry aborts the active turn’s per-turn signal synchronously (no await between reading the handle and aborting), so on the single-threaded loop it can never fire a torn-down controller.
Placement, not ordering, resolves the flag
operatorInterrupt is set when steering fires the per-turn abort and read at post-stream points all resolved by position in the existing flow (stream → validation → canReask :3032 → :3124 Cancel check → completion): (1) canReask (:3032) must also stop on operatorInterrupt, else the interrupted partial would auto-re-ask; (2) the executor skips validation on an interrupted turn — no validation-miss events for a turn the operator cut; (3) the operatorInterrupt branch sits immediately after the :3124 Cancel check, so a co-firing Cancel wins by position — no ordering rule to invent; (4) the flag is per-turn, reset when the loop starts turn N+1, so a stale flag can never abort or mis-route a later turn.
The discriminator
The real “interrupted vs natural” test is “did the turn emit a result”, not the flag alone: the executor already consumes a provider-normalized msg.type === 'result' (dag-executor.ts:2533), and a stream-abort yields none. If the interrupt lands just as the turn ends on its own, the turn produced its result → it completes or auto-drains (AD-4) regardless of the flag, and the interrupt is spent (a no-op). Only a turn that produced no result with operatorInterrupt set is an interrupted end. Because steering aborts only the per-turn signal, the node-level :3124 Cancel check is never tripped by steering.

Send & multi-turn

AD-3

Send is an ordinary prompt on the live session; delivery timing is the operator’s choice, not a provider limit

Binds
CAP-1, CAP-3, CAP-5, IAgentProvider.sendQuery.
Prevents
a new named steer() primitive; disqualifying any provider; holding a message “because the provider can’t do better”; interrupt-first modelling.
Rule
Three paths; interrupt (AD-2) is orthogonal to all of them, and only soft-inject is gated by provider transport:
• Queue (default, any provider): the registry holds the message; delivered as turn N+1 when the current turn ends naturally. Non-interrupting — the baseline.
• Send now (any provider): offered only once the agent is idle-after-interrupt (AD-9) — an ordinary prompt on an idle session → turn N+1 immediately. It does not itself interrupt.
• Soft-inject (CAP-5, provider- and spike-gated): where the provider folds a message into the running turn (claude streaming input; codex deferred), it arrives mid-turn with no interrupt. claude’s soft-inject rests on an unverified seam — whether AsyncIterable streaming input composes with the resume protocol (exercised only on a string prompt at the pin). The v1 floor is interrupt + Queue, which needs no spike; soft-inject ships when the spike clears — not v1-ready.
Interface
The only IAgentProvider change: sendQuery’s input may be an async iterable (stream) for soft-inject, plus an interrupt affordance — both reuse provider-native operations. No new named primitive.
AD-4new engine behavior

A steered node runs multiple provider turns on one live session; turn-end has two causes

Binds
CAP-2, CAP-3, the executor’s per-node turn loop.
Prevents
the node ending after its first turn while a steer is pending; an interrupt with an empty queue completing the node; validating a partial interrupted turn as real output; re-establishing a fresh session (losing the agent’s context).
Rule
A steered node continues on the SAME provider session across turns, reusing the session-resume seam the structured-output re-ask already uses — sendQuery with attemptResumeId on the same session (dag-executor.ts:2290). Each delivered operator message becomes the next turn’s input. This is the one genuinely new engine behavior.
Two causes
Natural end (agent finished on its own): the queue auto-drains — a queued message → run turn N+1; queue empty → node completes. Auto-delivery at the natural boundary is Queue’s contract (CAP-1). Interrupted end (operatorInterrupt set): the turn produced a partial result — no schema-valid output_format — which the executor must not validate, complete, or advance the DAG on. It always enters idle-await, whatever the queue holds — it never auto-fires. The only exits are the operator’s Send now (flush every queued message plus the one just typed, in written order → turn N+1) and the idle bound. This preserves the ratified Send now moment: after Stop, the operator adds the final correction before anything is sent.
The delta
The re-ask precedent (:2290) re-enters the loop on a validation miss (recoverable); steering re-enters on an interrupt from a state :3124 today treats as terminal — same seam, the operatorInterrupt branch is the new code.
Idle-await bound
On entering idle-await the executor arms a fresh 30-minute timer (owner-ratified) — reusing neither the streaming withIdleTimeout wrapper (:2298; no stream to wrap) nor its nodeIdleTimedOut outcome, which completes the node (:3118) and would ship the partial turn. On expiry the node takes an explicit node_failed branch: interrupted by operator, no redirect received.
How Cancel reaches idle
Idle-await has no stream, so the chunk-driven cancel-poll (:2312) is dormant — a /workflow cancel cannot reach it through the signal. Idle-await runs its own timer-driven poll of getWorkflowRunStatus at CANCEL_CHECK_INTERVAL_MS (:682), reusing shouldContinueStreamingForStatus (:700-702) and taking the existing Cancel ending when the run is no longer streamable. Idle-await resolves exactly once: the first of Send now, the cancel-poll, or the 30-minute timer wins — the other two are torn down. Resuming a 30-minute fail re-runs the node from scratch with a fresh session — the interrupted agent’s context is gone (no durable session for a steer, AD-5). (Rejected bounds: wait-forever — ties up the node, fragile in-process; complete-with-partial — ships garbage downstream.)

Scope & the record

AD-5

In-process only: the registry holds the live handle; detached is deferred

Binds
CAP-1, CAP-2, CAP-5; the web-dispatch executor (api.ts:3200-3228); the CLI detach path (cli/src/commands/workflow.ts:696-722).
Prevents
pretending steering can reach a run whose live session is in another process; re-introducing durable state to bridge that gap.
Rule
The in-process registry — keyed (runId, nodeId), holding the live session handle + an in-memory inbound queue, valid only while the node is running in this process — is the sole mechanism. A detached run (CLI --detach) has no reachable handle → steering is unavailable for it in v1: the UI states this, and Cancel still works; a detached node otherwise runs to completion on its own — there is nothing to “resume” while it is running (/workflow resume applies only if it later fails). No durable steering state: a server restart drops the live session; any in-flight steer is lost and the run resumes normally — the accepted v1 boundary, matching aion.
AD-6

The executor is the single writer of the operator transcript row

Binds
CAP-4, CAP-6; HITL/AD-3.
Prevents
a second appender to the node-message table; seq contention; an operator row whose position is unguaranteed; an operator row that cannot be attributed to its sender or reconciled against what the browser marked sent.
Rule
An operator message is an ordinary text row carrying three additive metadata fields — origin = 'operator', operator_user_id (the acting identity from resolveAuthContext, so CAP-4 attributes the message across a multi-user install), and message_id (the caller-stamped id from CAP-6, so the client can reconcile which sent messages became rows — AD-11). All three are additive on the .strict() metadata schema (workflows/src/schemas/node-execution.ts:29-43) + a regenerated api.generated; no migration (the column is already JSON). Written by the executor through the store at the point of delivery, placed by seq between the turn it redirected and the turn it caused. Delivered as a plain prompt, never resumeInteractions (an operator message has no tool_use_id). The row is a receipt for the record — the delivery vehicle is the live session. The server never writes it.
AD-7

Delivery emits no turn-start event from the steering layer

Binds
CAP-3, CAP-4, CAP-5; the executor; every adapter; the transcript record.
Prevents
a fabricated turn boundary corrupting the record the read half projects from.
Rule
Delivering an operator message — soft-inject mid-turn, or as the next turn after an interrupt — must emit no turn-start event from the steering layer; the turn boundary is where the agent’s own loop puts it. An adapter that cannot inject without signalling a new turn holds the message for the next boundary rather than fabricating one.

Confirmation & projected state

AD-8

Delivery confirmation is best-effort, claude-only, gated on the SDK bump

Binds
CAP-6, the UI status chip.
Prevents
making confirmation a mandatory interface function (would disqualify every provider but claude).
Rule
Confirmation reports arrival; it is not a delivery mechanism. Only claude echoes a caller-set uuid, and that echo needs @anthropic-ai/claude-agent-sdk ≥ 0.3.246 — so delivered is unreachable at the inherited pin 0.3.209 and becomes claude-only after that bump (Deferred). Until then the UI shows sent for every provider and never advances past it. Correlation is by id, never text or timestamp.
AD-9

The agent’s generating / interruptible state is projected in the core; both shells read it

Binds
CAP-1, CAP-2, CAP-3; the run-state projector; both dock shells; Track A/AD-1.
Prevents
each shell inferring mid-generation from raw state — forking the status channel across two surfaces; a persisted status enum re-introducing durable stop state.
Rule
The agent’s state inside node = running is a projected sub-state with two values: generating (a turn is streaming: interruptible, and soft-injectable where the provider offers it) and idle-after-interrupt (a turn was interrupted, the session is alive and awaiting the operator — where Send now is offered). Derived in the core from the live turn lifecycle, emitted as data on the node state the shells already consume. No new persisted status enum — the ghost of the rejected stopping/stopped states, correctly relocated inside running. The interrupting state in control-states.md is a UI-local optimistic transient (the brief window while an interrupt request is in flight), never a projected value — the core emits only the two. Both shells (Legacy + Console) render the composer dock from this one sub-state — the cross-shell parity invariant.

Cross-spec & routes

AD-10

CAP-4 reaches into the transcript spec; that change is made there

Binds
CAP-4, spec-readable-agent-transcript.
Prevents
this spine silently adding an item kind to another spec’s contract.
Rule
AgentHistoryItem there has kinds assistant | tool | lifecycle; an operator row is none, and Track A/AD-1 puts every row’s meaning in the shared core. The new item kind and its two-shell treatment belong to that spec’s own update, opened there before CAP-4 ships. Sequencing: an operator text row must not reach a live transcript until that reader recognizes origin='operator' (else it renders as agent text) — the reader change lands first.
AD-11

Send and Interrupt are new authorized routes; races fold forward, only a finished node refuses

Binds
CAP-1, CAP-2, CAP-5; the Send / Interrupt routes.
Prevents
an unauthenticated or cross-user steer mutating a run; a durable-marker / phase gate this model does not have; a 409 where the queue already absorbs the race.
Rule
Send and Interrupt are new routes — POST /api/workflows/runs/:runId/nodes/:nodeId/send and …/interrupt — resolving identity via resolveAuthContext under HITL/AD-7 (not a new grant). There is no phase / marker gate (no durable state exists): the route acts on the live registry handle.
Races
The queue absorbs them — no 409, and nothing is lost. A Send that arrives while an interrupt is in flight lands in the registry queue and waits there — when the interrupt lands, the node goes idle-after-interrupt, and the queue drains only on the operator’s Send now (AD-4), never automatically. A Queue message whose generating turn ends naturally is delivered at that natural boundary (CAP-1). The two drain rules differ by how the turn ended, not by a route branch. Soft-inject correlates to its target turn by the registry’s in-memory turn id, never a durable attempt-key.
Teardown
The last queue check: a Queue message landing after the loop’s final natural-end check but before the registry entry is torn down returns 409 finished (kept as a browser draft) — closing the one gap where a message could read sent yet never deliver.
Terminal reconciliation
On any terminal cause (finish, Cancel, or the 30-minute fail) the in-memory queue dies with the registry. The client keeps an observation ledger of generation-valid shared-queue receipts plus local successes, then reconciles against the message_id on operator rows actually written (AD-6); unmatched receipts restore as “Never sent”. Trigger is actual node-terminal evidence only (persisted node_completed/node_failed, or exact-scope purged-Ask projection incl. uniquely matched loop owners; answered resume needs resumed:true + later starts; ambiguity fails closed) — never a live refetch or run-level status alone. Cancel can publish run cancelled before the raw node event, so mounted run-detail views do 3 s read-only catch-up while executions stay unsettled and start a node-wide transcript drain only after the real event. A finished-iteration observer stays eligible; comparison still omits occurrence filters. Missing event/drain → fail closed. Finished mode still renders after Cancel flips the run non-live once recovery input is ready.
Global order
The single global order is the registry’s receipt order (server-side FIFO); AD-3’s “written order” is per-operator. Two docks may steer one node: there is no per-node steering lock — concurrent operators interleave in receipt order, attributed by operator_user_id (AD-6), not serialized.
Refusal
The only refusal is a Send / Interrupt to a node no longer running: node finished → 409 (the draft stays in the browser); and no live handle in this process (detached — AD-5) → a clear “not steerable here.”

Control states — the two dock controls

Both follow the agent’s projected sub-state (AD-9), never a remembered mode. The transition is symmetric and automatic: the moment the agent generates again, Send now reverts to Queue and Stop returns.
