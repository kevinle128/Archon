## Codebase Patterns

### Room width: drive the persisted ratio, never the separator drag
- **Where**: `e2e/ui/agent-tool-row-visual.spec.ts` `setRoomWidth`; `packages/web/src/lib/room-split-layout.ts`
- **Pattern**: To assert a measured room width (e.g. 460 ± 2 px), measure the resizable GROUP width via `#console-run-room` / `#legacy-run-room` parent, write the exact ratio into `localStorage['archon.run-room.ratio.<surface>']` (fractional percent allowed, clamped 24–60), and remount — `readRoomRatio` applies it on open. Do NOT drag the separator: the Console separator (`data-slot="console-panel-separator"`) is unstyled and zero-width (keyboard-only), and mouse steps can't reliably land inside a ±2 px window anyway.
- **Example**: `await page.evaluate(([k, v]) => localStorage.setItem(k, v), ['archon.run-room.ratio.console', String(ratio)])` then re-navigate.

### Closed `<details>` hides content from getByRole, not getByText
- **Where**: `e2e/ui/workflow-run-hitl-room.spec.ts` fixes in US-005
- **Pattern**: Playwright `getByRole` resolves through the accessibility tree — content inside a closed `<details>` is absent from it (`toHaveCount` → 0 even though the DOM node exists). `getByText` still matches (DOM-based) but `toBeVisible` fails. Tests asserting controls/payload inside a row must click the row `summary` (and the nested `Output` summary) first.

### Tailwind layered utilities vs unlayered theme rules
- **Where**: `packages/web/src/experiments/console/theme.css` `.console-root :focus-visible`
- **Pattern**: Tailwind v4 emits utilities inside `@layer utilities`; unlayered author CSS (theme.css) beats layered utilities regardless of source order or equal specificity. The console-global focus rule overrode `focus-visible:outline-accent-bright` with 30 %-alpha `--accent-ring`. Fix locally with the v4 trailing-bang important modifier: `focus-visible:outline-accent-bright!`.
- **Pattern**: `motion-reduce:transition-none` computes `transition-property: none`, NOT `transition-duration: 0s` — assert on `transitionProperty` when checking reduced-motion suppression.

### Chromium AX-tree assertions via CDP
- **Where**: `e2e/ui/agent-tool-row-visual.spec.ts` `summaryAxEvidence`
- **Pattern**: `DOM.getDocument` → `DOM.querySelector` → `Accessibility.queryAXTree` returns the accessible name/role/properties a real AT consumes. Correlate state via `backendDOMNodeId` (from `DOM.describeNode`) — nested disclosures can carry their own `expanded` prop, and the AX tree updates lazily after DOM toggles, so poll.

### E2E serves prebuilt web dist — rebuild after renderer changes
- **Where**: `e2e/lib/playwright/archon-runtime.ts` (`WEB_DIST_INDEX` = `packages/web/dist/index.html`)
- **Pattern**: Each worker's isolated Archon server serves the built SPA bundle, not a dev server. UI source changes are invisible to Playwright until `bun run build:web` regenerates `packages/web/dist` (gitignored — never commit). Symptom of a stale bundle: E2E page snapshot shows the OLD UI on every surface.
- **Example**: `bun run build:web && cd e2e && env -i HOME="$HOME" PATH="..." npx playwright test -c playwright.config.ts …`

### e2e deps + Playwright in this worktree
- **Where**: `e2e/`
- **Pattern**: The dev shell inherits poisoned `npm_config_local_prefix` / `npm_package_json` env vars from a parent npm lifecycle pointing at a DIFFERENT checkout (`/Volumes/WD_BLACK/workspace/opensource/Archon`). Plain `npm ci` in `e2e/` then reports "up to date" and installs nothing. Run npm/npx under a clean env: `env -i HOME="$HOME" PATH="/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin:/Users/agent/.bun/bin" <cmd>`.
- **Pattern**: Playwright browser build is pinned by `e2e/package-lock.json` (`@playwright/test@1.60.0` → `chromium_headless_shell-1223`). A browser installed for another checkout's version will NOT be found — run `npx playwright install chromium` inside this worktree's `e2e/` once.
- **Example**: `cd e2e && env -i HOME="$HOME" PATH="..." npx playwright test -c playwright.config.ts ui/workflow-run-hitl.spec.ts --grep "HITL.*readable tool row"`

### Tool row presentation contract
- **Where**: `packages/web/src/lib/tool-presentation.ts`
- **Pattern**: All provider-name/policy decisions live in the pure module; renderers must stay markup-only. Family resolution order is fixed: bounded `mcp__server__tool` → exact normalized alias (case-fold + strip `_`/`-`, name ≤128 code units) → known input-key inference → Codex name-only shell (absent/empty input + command-like/overlong name) → generic.
- **Pattern**: "Command-like" was pinned to: whitespace within the first `MAX_HEADLINE_SOURCE_CODE_UNITS` code units, or name longer than that cap entirely.
- **Example**: `search_replace` → `file` (exact match beats substring); `mcp__github__create_issue` → `generic` with label `github · create_issue` regardless of input keys.

### Controlled `<details>` + React + happy-dom contract (reuse for US-004 console row)
- **Where**: `packages/web/src/components/workflows/NodeRoom.tsx` `ToolHistory`
- **Pattern**: Control `<details open={open}>` via state; in `onToggle`, ignore bubbled nested toggles with `event.target !== event.currentTarget`, and treat `event.currentTarget.open === open` (state) as a programmatic echo — real user activation flips DOM `open` away from rendered state before the event reaches React. Auto-open = `useEffect(() => { if (!open && !touched && initialOpen) setOpen(true) })` — no path ever calls `setOpen(false)` itself.
- **Pattern**: happy-dom fires React `onToggle` on summary `click` (MouseEvent, bubbles) but does NOT implement summary's keydown→activation default — tests dispatch keydown + the synthesized `click` a real browser emits. `summary.focus()` sets `document.activeElement`. Programmatic `open` writes do NOT produce a React-visible toggle echo in happy-dom (real browsers DO — hence the guard).
- **Pattern**: happy-dom types don't overlap lib.dom (`activeElement: HTMLElement|SVGElement` is their own type) — cast `as unknown as Event` for `win.MouseEvent`/`win.KeyboardEvent` in `dispatchEvent`, and `as unknown as Element`/`HTMLElement` for queried nodes.
