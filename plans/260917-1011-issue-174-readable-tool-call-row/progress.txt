## Codebase Patterns

### e2e deps + Playwright in this worktree
- **Where**: `e2e/`
- **Pattern**: The dev shell inherits poisoned `npm_config_local_prefix` / `npm_package_json` env vars from a parent npm lifecycle pointing at a DIFFERENT checkout (`/Volumes/WD_BLACK/workspace/opensource/Archon`). Plain `npm ci` in `e2e/` then reports "up to date" and installs nothing. Run npm/npx under a clean env: `env -i HOME="$HOME" PATH="/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin:/Users/agent/.bun/bin" <cmd>`.
- **Pattern**: Playwright browser build is pinned by `e2e/package-lock.json` (`@playwright/test@1.60.0` → `chromium_headless_shell-1223`). A browser installed for another checkout's version will NOT be found — run `npx playwright install chromium` inside this worktree's `e2e/` once.
- **Example**: `cd e2e && env -i HOME="$HOME" PATH="..." npx playwright test -c playwright.config.ts ui/workflow-run-hitl.spec.ts --grep "HITL.*readable tool row"`

### Tool row presentation contract
- **Where**: `packages/web/src/lib/tool-presentation.ts`
- **Pattern**: All provider-name/policy decisions live in the pure module; renderers must stay markup-only. Family resolution order is fixed: bounded `mcp__server__tool` → exact normalized alias (case-fold + strip `_`/`-`, name ≤128 code units) → known input-key inference → Codex name-only shell (absent/empty input + command-like/overlong name) → generic.
- **Pattern**: "Command-like" was pinned to: whitespace within the first `MAX_HEADLINE_SOURCE_CODE_UNITS` code units, or name longer than that cap entirely.
- **Example**: `search_replace` → `file` (exact match beats substring); `mcp__github__create_issue` → `generic` with label `github · create_issue` regardless of input keys.

### Controlled `<details>` + React + happy-dom contract (reuse for US-004 console row)
- **Where**: `packages/web/src/components/workflows/NodeRoom.tsx` `ToolHistory`
- **Pattern**: Control `<details open={open}>` via state; in `onToggle`, ignore bubbled nested toggles with `event.target !== event.currentTarget`, and treat `event.currentTarget.open === open` (state) as a programmatic echo — real user activation flips DOM `open` away from rendered state before the event reaches React. Auto-open = `useEffect(() => { if (!open && !touched && initialOpen) setOpen(true) })` — no path ever calls `setOpen(false)` itself.
- **Pattern**: happy-dom fires React `onToggle` on summary `click` (MouseEvent, bubbles) but does NOT implement summary's keydown→activation default — tests dispatch keydown + the synthesized `click` a real browser emits. `summary.focus()` sets `document.activeElement`. Programmatic `open` writes do NOT produce a React-visible toggle echo in happy-dom (real browsers DO — hence the guard).
- **Pattern**: happy-dom types don't overlap lib.dom (`activeElement: HTMLElement|SVGElement` is their own type) — cast `as unknown as Event` for `win.MouseEvent`/`win.KeyboardEvent` in `dispatchEvent`, and `as unknown as Element`/`HTMLElement` for queried nodes.
