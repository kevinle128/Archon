## Mission and current status

**Desired outcome (two independent deliverables, user confirmed "làm cả 2"):**

1. **Process leak on workflow stop (bug, highest priority).** When a run is cancelled/abandoned, a node times out, or the server shuts down (PM2 restart), Archon must leave no engine-spawned process running — children _and_ grandchildren — across every spawn point (all 8 providers + bash/script/until_bash nodes). The only accepted residue is a daemon that itself calls `setsid`/double-forks (documented limit; needs container isolation).

## Decisions and rationale

1. **Fix at the shared layer, not per-provider or Claude-only.** Evidence: every spawn site kills only the direct child pid and none uses a process group — Claude local (SDK-managed, `packages/providers/src/claude/provider.ts:1602-1607` only `closeQuery()`; the `spawnClaudeCodeProcess` hook exists only for containers at `provider.ts:837`), Codex (SDK `spawn({signal})`, `codex/provider.ts:1053-1067`), Grok (`grok/provider.ts:59`, kill at 202-204), omp (`community/omp/provider.ts:62`, 208-210), qodercli (`community/qodercli/provider.ts:68`, 99-101), DeepSeek ACP (`community/deepseek/acp-client.ts:240-248`), Devin ACP (`community/devin/acp-client.ts:536-542`), OpenCode (`community/opencode/runtime.ts:123`), and bash/script nodes via `execFileAsync` (`packages/git/src/exec.ts:68-72` — no `signal`, Node timeout SIGTERMs the direct pid only). The user explicitly asked that Devin, Codex, Grok, DeepSeek and omp be covered, not just Claude.
2. **Primitive = spawn in own process group + tree kill TERM → grace → KILL.** De-risked twice on Bun 1.4.2: `node:child_process.spawn({detached:true})` and `Bun.spawn({detached:true})` both produce `pgid === pid`; `process.kill(-pid,'SIGTERM')` leaves a `trap "" TERM` child alive, `process.kill(-pid,'SIGKILL')` clears everything. The escalation to KILL is mandatory — the Mac mini had exactly such a `sh -c trap "" TERM; while :; do sleep 1; done` orphan.
3. **Helper location: `@archon/paths`** (e.g. `process-tree.ts`: `terminateProcessTree(pid, {graceMs})`, POSIX `kill(-pgid)` with `kill(pid)` fallback and ESRCH tolerated; Windows `taskkill /PID <pid> /T /F` — precedent `packages/workflows/src/plannotator-gate-supervisor.ts:628`). Rule of Three is satisfied (9 call sites). Do not set `detached` on win32 (different semantics); `taskkill /T` handles the tree.
4. **Cancel detection for subprocess nodes reuses the AI-node mechanism**: poll `deps.store.getWorkflowRunStatus` every `CANCEL_CHECK_INTERVAL_MS` (10 s, `dag-executor.ts:683`) with `shouldContinueStreamingForStatus` (`dag-executor.ts:2311-2330`), abort → tree kill, classify the node result the way the AI path does around `dag-executor.ts:2920`. This is cross-process safe (CLI/web abandon only writes DB status; the executor that owns the child detects it).
5. **Server shutdown must abort in-flight nodes and await a bounded settle** before `pool.end()` / `process.exit(0)` (`packages/server/src/index.ts:982-1030` currently stops adapters, flushes telemetry, closes the pool, kills nothing). Without the settle, `node_failed`/run `failed` writes never land and runs stay `running` forever after each PM2 restart (9 restarts observed; last one `2026-09-19T23:50:59` via SIGINT). Registry shape precedent: `packages/workflows/src/steering-registry.ts`.
6. **Codex is the one unresolved spawn site.** The codex-sdk spawns internally; unknown whether it exposes a spawn hook or the child pid. Decision: scout the SDK API during planning; if no hook, document the limitation rather than hack (e.g. no wrapper-script tricks).
7. **Tail-first design:** server adds `order=desc` to the existing cursor mode (DB already has `throughSeq`; `listNodeMessages` at `packages/core/src/db/workflow-node-messages.ts:174-197` is `ORDER BY seq ASC` only) — query DESC `LIMIT n+1`, reverse, keep `messages` ascending, add `hasOlder`/`prevCursor`; the existing `highWatermark` field already gives the newest seq on the first call. Client: tail mode is **opt-in** on the shared helper `drainNodeMessages` (`packages/web/src/lib/node-message-pages.ts:216-263`) because `ConsoleNodeRoom.tsx:548` and `ConsoleExecutionHistory.tsx:173` share it and would lose access to older history if tail became the default. Wire the legacy `NodeTranscriptPane` only; console adoption is a follow-up.
8. **Rejected alternatives:** virtualization (unnecessary once the window is 100 rows; note as follow-up if still laggy); making tail the default everywhere (console regression); a cwd-based orphan reaper (violates process-boundary rule); killing in-container processes through the `docker exec` client (listed as an explicit non-goal — it does not cross the boundary; container path already uses a pidfile + `kill -SIG -pgid`, see `packages/providers/src/claude/container-spawn.ts:100-125`).
9. **Two PRs, phase 1 first** (leak), because it is what took the machine down.
