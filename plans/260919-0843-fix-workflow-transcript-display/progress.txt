## Codebase Patterns

### Console wildcard border pin defeats Tailwind border-* utilities
- Where: `packages/web/src/experiments/console/theme.css` (`.console-root * { border-color: var(--border) }`)
- Pattern: Unlayered wildcard border pin beats layered Tailwind `border-warning` / `border-border-bright`. Restore intended colors with a more-specific unlayered rule (Raw toggle already did this; Ask card uses `[data-ask-card] { border-color: var(--warning) }`).
- Example: `.console-root [data-ask-card] { border-color: var(--warning); }`
- Gotcha: changing theme.css requires re-pinning its sha256 in visual-config.json AND regenerating the `ui.visual` runner digest in run-ui.json; pin AFTER prettier rewrites the file.

### Raw focus/hover/open all flip to primary text + bright border
- Where: `NodeRoom.tsx` + `ConsoleAgentHistoryList.tsx` Raw toggle closed-state classes
- Pattern: closed = secondary + quiet border; `hover:` AND `focus-visible:` must both promote to primary text + bright border (open state already primary). Missing `focus-visible:text-text-primary` fails the tool-row visual gate even when hover works.
- Example: `... hover:text-text-primary focus-visible:border-border-bright focus-visible:text-text-primary`

### Deterministic real-server transcript E2E via `prepareTranscriptDisplayRun`
- Where: `e2e/lib/playwright/archon-runtime.ts` (`TRANSCRIPT_*` exports + `prepareTranscriptDisplayRun()`); spec `e2e/ui/workflow-transcript-display.spec.ts`; fixture `e2e/fixtures/workflows/e2e-transcript-display.yaml`.
- Pattern: The e2e-fake provider cannot emit structured output, so the fixture's `output_format` node (`group.structured`, a `loop_group` child to exercise nested resolution) and `plain` sibling skip via an unsatisfiable `when: $seed.output == '...'` guard on a `bash:` producer (whole-output compare is allowed on bash; AI producers are rejected by the loader). After `workflow run` completes, the helper reads each node's minted `occurrence_id`/`attempt_id` back from its `node_skipped` event row and seeds matching `metadata.execution` + `text_mode: 'delta'` fragments plus ineligible rows into `remote_agent_workflow_node_messages` — the durable shape, while request/API/storage stay real. `ghost` (started/completed events, no definition row) covers the deleted-definition fallback.
- Gotcha: assert unwrap by polling `not.toContainText(<exact canonical envelope>)` — the raw envelope contains the inner text as a substring, so `toContainText(inner)` alone passes prematurely before the async definition resolves.
- Note: `loop_group` requires a completion channel (`until_bash: exit 0` here); e2e deps install with `bun install` in `e2e/` (npm leaves a stub tree — lockfile has no resolved URLs); CI uses `npm ci --prefix e2e`.

### One-string output_format → unwrapped assistant text
- Where: `packages/web/src/lib/agent-history.ts` — `singleStringSchemaKey()` + `presentedText()`; applied per projected assistant item inside `buildAgentHistory()` after `projectTextTranscript()`.
- Pattern: The matched definition node's `output_format` arrives as optional `outputFormat` on `AgentHistoryInput`. Unwrap only when the schema is an object with exactly one `type:'string'` property AND the whole text is the canonical `JSON.stringify` of that one-key object; every other shape returns the original bytes (fail closed). Never mutates rows; per-item, so tool rows stay block boundaries.
- Example: `'{"report":"# Title"}'` + `{type:'object',properties:{report:{type:'string'}}}` → assistant text `# Title`.

### MessageChunk textMode → transcript metadata.text_mode
- Where: `packages/providers/src/provider-types.ts` (MessageChunk.textMode?: 'complete' | 'delta' | 'snapshot'); persistence forwarding in `packages/workflows/src/dag-executor.ts` — `...(msg.textMode !== undefined ? { text_mode: msg.textMode } : {})` in BOTH the direct-node and loop-node transcript paths.
- Pattern: Providers declare the text boundary semantic on the chunk; the executor forwards it into row metadata verbatim. No DB/schema change needed — `metadata` is a free-form JSON column validated by `packages/workflows/src/schemas/node-execution.ts`.
- Example: `return [{ type: 'assistant', content: update.content.text, textMode: 'delta' }];`

### Transcript execution scope / attempt rotation
- Where: `packages/workflows/src/transcript-execution-scope.ts` — `newTranscriptAttempt(scope)` returns `{ ...scope, attempt_id: randomUUID() }` (same occurrence_id, new attempt).
- Pattern: Every provider re-ask inside a loop MUST rotate the scope before the next pass, or failed + repaired text land in the same attempt. The invalid-structured-output branch already did this (~dag-executor.ts:6630); the missing-output branch (~6660) previously only bumped `reaskAttempt` — now it rotates too.
- Example: `reaskAttempt++; iterationExecutionScope = newTranscriptAttempt(iterationExecutionScope); reaskErrors = ['no JSON object was found in the response']; continue attempts;`

### Executor test infra for transcript rows
- Where: `packages/workflows/src/dag-executor.test.ts` — `runNodes()` helper + fake transcript store capture; `runNodes` accepts an optional provider name (added `provider` param this iteration) so node `provider:` fields resolve through `workflowProvider`.
- Pattern: Assert on captured append payloads: `textRows[i].payload` for text, `textRows[i].metadata.execution` for `{ occurrence_id, attempt_id, retry_epoch, text_mode }`.
- Gotcha: `bun test -t` filters run fast; the full file is ~48s/629 tests. Test files are in the repo eslintignore — lint only production files when checking warnings.

### ACP bridge test fakes
- Where: `packages/providers/src/community/{devin,deepseek}/acp-client.test.ts`
- Pattern: Fake ACP child processes emit session/update JSON-RPC notifications; to test split streaming, emit two `agent_message_chunk` notifications ('Hel' then 'lo') before the terminal result and assert two ordered delta chunks.

### happy-dom prototype stubs are process-global — make them writable
- Where: `packages/web/src/components/workflows/WorkflowExecution.test.tsx` (`installHappyDom`); victim example `ConsoleNodeRoom.test.tsx` `stubRect`.
- Pattern: `Object.defineProperty(win.HTMLElement.prototype, <prop>, {...})` without `writable: true` installs a NON-writable prototype member on the shared happy-dom prototype. Any later file in the SAME `bun test` process that does `el.<prop> = fn` throws `TypeError: Attempted to assign to readonly property`. The package test script splits `src/components/` and `src/experiments/` into separate processes, so the hazard only detonates in combined invocations (focused gates, `bun test src/`). Always pass `writable: true` on prototype stubs; instance-level `defineProperty`/`=` stays the normal pattern for consumers.
