# Doc standards — UX spine: structure + prose

Applied late, after Finalize. `bmad-review` lenses `structure` then `prose` only, over
`_bmad-output/planning-artifacts/ux-designs/ux-Archon-agent-node-room-2026-09-09/DESIGN.md` (5,000 words) and
`EXPERIENCE.md` (6,208 words). Advisory only — no file was changed.

**Purpose read.** These two documents exist to let a web developer build one transcript on two
token surfaces without a second design conversation, and to let a later auditor find the reason for
each accepted shortfall.

**Structure model.** Reference/Database for both bodies: a builder jumps to the component or state
they implement, so each section must answer alone. DESIGN's Open Questions follows Pyramid
(recommendation first, then evidence). Both bodies match the canonical spine order
(`bmad-ux/references/validate.md:37`): DESIGN Brand & Style → Colors → Typography → Layout & Spacing
→ Elevation & Depth → Shapes → Components → Do's and Don'ts, plus Open Questions; EXPERIENCE holds
all eight required defaults in order, with Responsive and Inspiration correctly present.

**Style guide.** Microsoft Writing Style Guide is the configured baseline. British spelling
(`colour`, `normalization`/`recognises` mix), the terse declarative voice, and one-clause-per-line
Markdown are intentional and preserved. No Microsoft-preference rewrite is proposed — those would be
preference, not comprehension.

**Scope.** Structure and prose only. Correctness, accessibility and token accuracy are other
reviewers' findings. Where a contrast number appears below, the finding is that two copies of it
disagree — not which value is right.

## Checked, no findings

- **Table well-formedness.** Every table in both files has a matching header, delimiter and cell
  count. Alignment padding is inconsistent, which Prettier owns, not a reader.
- **Heading levels.** No skipped level in either file. DESIGN has no H1 by design — the spec puts
  identity in frontmatter.
- **Subject-verb agreement, singular "they".** Every instance is plural-verb and correct: "They
  open", "They scan", "They press", "a keyboard reader … cannot see where they are". No "they opens".
- **Tense and voice.** Present tense for specification, past for recorded decisions, throughout.
  Consistent.
- **Other cross-references.** All resolve to real sections: DESIGN → EXPERIENCE Component Patterns;
  DESIGN Components → Tool body; DESIGN Colors → Status (×3); EXPERIENCE → DESIGN Colors; EXPERIENCE
  §Component Patterns Body bar → State Patterns → Output truncated; the whole Open Questions "Where it
  now lives" column. Only N5 misses.

## Summary

17 recommendations: 6 blocking, 11 non-blocking, 2 preserve notes. Accepting every cut removes about
220 words of 11,208 — **2%**. That number is the verdict on dead weight: there is none. Every
blocking finding is a contradiction between two copies of one fact, and each fix is one sentence.
No comprehension trade-off: nothing proposed for cutting is the only statement of its rule.
