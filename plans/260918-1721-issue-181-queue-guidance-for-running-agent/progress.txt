## Codebase Patterns

### Process-singleton module (event-emitter pattern)
- **Where**: `packages/workflows/src/event-emitter.ts:361-375`, mirrored in `steering-registry.ts`
- **Pattern**: module-level `let instance: T | null = null`; `getX()` lazily constructs; separate `createX()` returns isolated instances for tests (never shares singleton state); reset via `clearForTests()`/`resetX()`
- **Example**: `getSteeringRegistry()` (prod) vs `createSteeringRegistry()` (tests)

### Package exports + test chain (packages/workflows)
- **Where**: `packages/workflows/package.json`
- **Pattern**: every importable module gets an explicit `"./name": "./src/name.ts"` entry in `exports`; the package `test` script is an explicit `&&`-chained list of `bun test <file>` invocations — new test files MUST be appended or `bun run validate` silently skips them
- **Gotcha**: `bun --filter @archon/workflows` does NOT match — run `bun run type-check`/`bun test` from inside `packages/workflows/` instead

### Lint scope
- `*.test.ts` files are in the eslint ignore list — passing a test file explicitly to eslint emits a "file ignored" warning that fails `--max-warnings 0`; use `--no-warn-ignored` or lint only source files

### Git
- Pre-commit runs lint-staged (eslint --fix + prettier on staged files) — works fine, no bypass needed
- `git commit -m "$(cat <<'EOF' ... EOF)"` heredoc broke in this shell; multiple `-m` flags worked
