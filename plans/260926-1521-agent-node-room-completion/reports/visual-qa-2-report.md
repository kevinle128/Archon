- **Idle after interrupt (s3)** in both shells: `WILL SEND · 1`, the two disclosure lines, `Send now`, and the status `agent idle · Send now delivers`.
- **Auto-send** in both shells:
  - After `PUT …/auto-send {enabled:true}`, the band header reads `saved to server · Auto-send on`, as in the mockup.
  - Stop did **not** trigger auto-send: the item stayed `queued`.
  - After the redirect turn's natural reply, auto-send dispatched exactly one item (`AUTO:` went from `queued` through `dispatching` to `sent`), and then the node finished.
- **Per-item `Send now` is absent everywhere.** Every provider reports `soft_injection: false`. The only `Send now` in the DOM was the dock-level control in idle-after-interrupt. This was checked on the Claude, OMP and Codex rooms in both shells, while generating and while idle.

  - Claude, one queued item: `sent` then `delivered` (display gap is VQ2-2).
  - Claude, two items in one turn: `sent` only, which is correct because the acknowledgement covers a single message id.
  - OMP and Codex: `sent`, correct for providers without delivery acknowledgement.
- **Restart recovery (s8)** in both shells:

- **Advisor row:** a boxed `ADVISOR` card ("The advisor responded, but its answer is encrypted…"), in sequence order.
- **Thinking rows:** collapsed `▶ THINKING` rows in sequence on the haiku nodes.
- **Prompt row:** present at the top of each execution, with actor and source attribution (label issue is VQ2-9).

## Mockup vs contract drift and questions (not logged as defects)

- **Blank `Send now` with items waiting.** With `WILL SEND · 1` and an empty field, `Send now` is `aria-disabled`, although its accessible name ends `· 1 message will send`. `EXPERIENCE.md:272` says Send now "delivers everything and resumes the node". The e2e spec `agent-interrupt-redirect.spec.ts` ("blank Send now … issue no request") asserts the inert behaviour on purpose. Is a waiting item without a typed redirect meant to be undeliverable until auto-send or the 30-minute timeout?
- **`Stopping…` is per-tab.** A second tab on the same node keeps showing `Stop` until the idle state arrives (`app-legacy-claude2-*` vs Console). Harmless, but not shared across tabs or operators.
- **Retries inline vs selector.** The Legacy mockup draws `RUN 1 · FAILED` and `RUN 2 · RETRY` inline in one transcript. The app shows one execution per selector option, so an inline run header appears only when one execution spans several occurrences.
- **OMP capability comment.** `omp/capabilities.ts` (`interruptedToolStatus: false`) says an open tool "settles 'unknown'". The real RPC run returned a per-tool `Command aborted`, and the executor emitted `tool_outcome: interrupted`, so the `⚠` is backed by evidence. The comment is stale; the UI is honest.
- **Recovery prefix.** The app keeps `started HH:MM ·` in the recovery meta; the mockup omits it (vq-fixes decision, unchanged).
