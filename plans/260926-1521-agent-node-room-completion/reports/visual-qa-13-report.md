## Method

- **Isolated servers.** New scratch dir `…/scratchpad/vq13-1790712460/`. Two homes (`home`, `homef`), each with a DB copied through `sqlite3 ~/.archon/archon.db ".backup …"` plus `config.yaml` and `credential-key`. The only config change is `assistants.claude.advisorModel: opus` (as round 12). Real server on **3385**. Fake-provider server on **3386** (`ARCHON_E2E_FAKE_PROVIDER=1`). Both with the brief's env line. Vite on 5253 → 3385 and 5254 → 3386. Mockups served by me on **8795**. Startup cleanup reported `removed: 0` on every boot (8 boots of the real server). The codebase is a new scratch git repo (`wrk/`) with a local bare `origin`, registered on both servers. Every run was dispatched over HTTP. Operator header `X-Archon-User: vq13-operator`.
- **Providers.** Real subscriptions: Claude sonnet and haiku, Codex gpt-5.5, OMP `xai-oauth/grok-4.5`, Grok ACP, Grok `--single` (`output_format`), DeepSeek `alibaba/deepseek-v4.1-flash`. Qoder, Pi, Copilot and OpenCode were skipped. The two 30-min idle runs used real Claude on 3386.
- **Capture.** Two Playwright drivers (1440×900), one per server, each with one Console page and one Legacy page. Measured widths: Console **520 px**, Legacy **460 px**. All 32 mockup crops (8 sub-states × {prompt, loop} × {Console, Legacy}, `codex · queue only`) and the two static sheets were captured again.
- **Timing.** The round-12 toolkit, with three additions:
  1. Every rAF terminal watcher now records the **needle count** (how many times the queued item text is on screen) in each frame, so "terminal room with the item missing" is a direct per-frame check.
  2. The driver logs every `GET …/runs/<id>` and `GET …/nodes/<id>/queue` response per page (run status, `execution_state`, `node_outcome`). This gives the time of the **first server read that reports the node terminal** in each page, and "a `Running` frame after that read" is a mechanical count. A `Running` frame that is still on screen more than 50 ms after that read counts as a violation (the observed read → repaint lag is 4–41 ms).
  3. Focus watchers name the focused element by `data-testid`, and a new rAF watcher (`frows`) records focus, the number of transcript rows in the scroller and the selected execution in the same frame.
- **Definition of "promptly" for VQ12-4 (set before the runs).** In the sending shell, no frame with `SENDING`, `Stop` or `Queue` may start more than 100 ms after the first frame in which any shell shows the node terminal. Round 12's defect was ~950 ms.
- **Harness confound (disclosed).** From restart batch B1 until I noticed it, surviving tabs piled up in the real driver's browser context (34 pages against one origin). Chrome allows six HTTP/1.1 connections per host, so reads and SSE streams in that window could be delayed. This affects B2–B6, RFL2, FOL and the first cold-load set. A delay can only make a stale `Running` or a missing band more likely, so the zero counts in those batches are not weakened, but their latencies are not comparable. I closed the pile-up and re-ran the timing-sensitive parts clean: RFL3 (loop focus), B7 (outage) and `cold-clean.json` (cold loads, 3 repetitions). The numbers quoted below for those three come from the clean runs.
- **Pairs.** `pair-*.png` = mockup left, app right. Evidence in `evidence/visual-qa-13/`: screenshots, pairs, `outage-*.png`, and `data/` (`timing-summary.json`, `*-abandon.json` with rAF frames and GET logs, `fin-FIN*.json`, `*-focus.json`, `B*-recab2.json`, `B3-postrestart.json`, `B4/B5/B6/B7-surv.json`, `cold-clean.json`, `f75-*.json`, `I1/I2-shot.json`, `I2-keystroke.json`, `idle-fail.log`, reap files, `axe.json`, and the analysers `vq.py`, `finsum.py`, `recsum.py`).
