# Soft injection (per-item Send now) — report

Date: 2026-09-30 (Asia/Saigon). Branch `worktree-agent-a4b1bef9c53f33b3c`, forked from `develop-2` @ `8a888e98`.

## Outcome

Per-item `Send now` now delivers one queued message into the live turn without Stop on **Claude** and on **Grok (ACP transport)**. Every other in-scope provider stays queue-only, each with its own evidence below. Live evidence: 13 Claude cycles and 4 Grok cycles, each driven from one shell and watched from the other, plus two e2e specs on the fake provider.

## What was wrong

1. `soft-injection-spike.ts` capped the run at `maxTurns: 1` while its prompt needs three tool calls. The cap cut the first turn off, so the injected message started a second turn and the run looked like a "second result". Raised to 20, with a comment. Re-run through the pushable input the provider now uses (not `streamInput`): one result, marker in the first result, echo with the injected uuid.
2. Nothing wrote the operator row for a soft-injected message. The queue entry moved to `sent` and later `delivered`, but the transcript never showed the message. The executor now appends the operator row the moment the turn accepts the message (`createTranscriptSoftInjection`, `dag-executor.ts`), under the turn's current transcript attempt. The optional `operatorUserId` rides on the executor-side request only. The provider handler still gets `{messageId, text}`.
3. The web dock removed the item from the band as soon as the POST resolved, so the message showed nowhere until the transcript's next poll (up to about 1 s). `resolveSendNowItemSuccess` now keeps it as an in-flight (`sending…`) row until the transcript renders its row. That is the same handoff a typed Send now already uses. After the change there were 0 frames with the item shown nowhere in any of the 13 Claude cycles.

## Implementation

- `packages/providers/src/claude/provider.ts`: `singleTurnInput` is replaced by `createLiveTurnInput` (prompt first, then open for pushes, `push` returns false once closed). `ready(handler)` registers right after the query exists. The handler pushes one `SDKUserMessage` with `uuid = messageId` and resolves true only if the open input took it. It refuses after Stop. Unregistered with the input close on result, error, Cancel and finally. `--replay-user-messages` is on whenever `operatorMessageId` is set or a soft-injection channel is offered. The existing `isReplay` branch turns the echo into `operator_delivery_ack`, and the existing executor path moves `sent` to `delivered`.
- `capabilities.ts` (Claude): `softInjection: true`, with the corrected evidence. Matrix regenerated.
- `grok/acp-client.ts` + `provider.ts`: `_x.ai/interject` `{sessionId, text}` while the prompt is in flight. The agent answers `{result: {status: 'queued'}}`. A refusal is logged (`grok.acp_interject_failed` / `_not_queued`) and resolves false. `capabilities.ts` (Grok): `softInjection: true`, `deliveryAck` stays false.
- Fake provider: `e2e-fake-soft-inject` id (env-gated like `e2e-fake`) accepts messages during its bounded wait, then echoes each id and answers it inside the same turn. The default `e2e-fake` is unchanged and queue-only.
- Executor/registry: `createSoftInjectionController(onAccepted?)`, `SoftInjectionDelivery`.

## Concerns

- **Grok `--single` turns.** The capability is per provider, but a `--single` turn reports `turn_not_interruptible`, which makes `steeringSubState()` return undefined for that turn (`steering-registry.ts:310`). The dock then offers no `Send now`, and the send route answers 409 `soft_injection_unavailable` (`api.ts`, `steeringSubState() !== 'generating'`). I read this from source; I did not run a `--single` Grok node live.
- **No delivery ack on Grok.** An injected item stays `sent` for good. That is accurate (the transport accepted it) but it never reads `delivered`.
- **Late injection.** A message accepted after the model's last step and before `result` is dropped by the transport when the input closes (Claude), or queued to the next turn (Grok ACP). Its entry stays `sent`. The window is the gap between the final tool result and `result`.
- **Operator row position.** In both shells the injected operator row renders above the still-running tool card, although it was sent after the tool started.
- **Replay flag side effect.** `--replay-user-messages` is now on for every interruptible Claude turn that has a soft-injection channel, so the turn's own prompt echo also yields an `operator_delivery_ack` with a non-matching id. The store update is a no-op for it.
- The first Grok cycles returned 409 because the SDK's `request` returns Grok's `{result: {status}}` wrapper and my first unit fake used the unwrapped shape. The live run caught it; the fake now matches the wire shape.
