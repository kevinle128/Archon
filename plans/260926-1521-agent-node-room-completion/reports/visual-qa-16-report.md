## Method

- **Isolated servers.** New scratch dir `…/scratchpad/vq16-1790791870/`. Two homes (`home`, `homef`), each with a DB copied through `sqlite3 ~/.archon/archon.db ".backup …"` plus `config.yaml` and `credential-key`. The only config change is `assistants.claude.advisorModel: opus` (as in rounds 12–15). Real server on **3455**, fake-provider server on **3456** (`ARCHON_E2E_FAKE_PROVIDER=1`), both with the brief's env line. Every startup cleanup reported `removed: 0`. The codebase is a new scratch git repo (`wrk/`) with a local bare `origin`, registered on both servers. Every run was dispatched over HTTP with `X-Archon-User: vq16-operator`. `git for-each-ref refs/archon` in this repo stays empty.
- **Web servers.** Vite on 5323 → 3455 and 5324 → 3456, each started with **both** `PORT` and `VITE_API_PORT` set to its own API port. **Port proof:** a run that exists only on 3456 (`4398ee3b…`, 404 on 3455) renders through 5324, and a run that exists only on 3455 (`41e1df1d…`, 404 on 3456) renders through 5323. Every request of those page loads, and every `__dashboard__` EventSource, went to `localhost:5323` / `localhost:5324` (`data/portproof-real.json`, `data/portproof-fake.json`). No request went to 3090. Mockups were served by me on **8798**.
- **Shells.** The Console shell is gone. The redesigned run detail is the only room, at `/workflows/runs/:runId?node=<id>`. Each check drives two tabs of that page, **tab A** and **tab B**, **each in its own browser context** (the round-15 connection-pool lesson). A third context is added where a check needs it: a cold-join observer, a survivor, a companion. Tab A and tab B play the roles that Console and Legacy played in earlier rounds (sender / stopper alternating). Measured room width at 1440 × 900: **460 px** in every capture. Narrow check: 1000 × 800, where the room switches to the single-column layout (752 px, `Back` instead of `Close`).
- **Providers.** Real subscriptions: Claude haiku (soft-inject cycles, steering, idle, loop) and sonnet (B run), Codex gpt-5.5, OMP `xai-oauth/grok-4.5`, Grok ACP, Grok `--single` (`output_format`), DeepSeek `alibaba/deepseek-v4.1-flash`. Fake providers: `e2e-fake` (queue-only) and `e2e-fake-soft-inject`. Qoder, Pi, Copilot and OpenCode were skipped.
- **Toolkit** (`scripts/`). The round-15 driver, repointed to the redesigned route. It keeps the round-15 rAF key (`pill|rec|btns|ta|bands|status|al|nc|del|hint|rest|focus`), so the round-14/15 analysers (`vq.py`, `fin14sum.py`, `outsum15.py`, `coldsum.py`, `recabsum.py`) run unchanged. Changes for this round:
  1. The key gets a 13th field `sn`: the number of per-item `Send now · <message>` buttons. `btns` no longer counts them, so `Send now` in `btns` is only the dock button (otherwise every inherited "`Send now` = idle" rule misreads a soft-inject dock).
  2. `setup16.js`: the soft-inject cycle sampler (per animation frame, sender + observer + a **cold-join** tab opened 1.5 s or 12 s after the click). Per band item it records `*` (`sending…`), `x` (has `✕`) and `s` (has its own `Send now`), each operator row with its delivery word, and `document.activeElement`. `analyze16.py`, `gaps16.py` and `orderseq16.py` read it.
  3. `out16.sh`: the round-15 outage check plus a third run **C** on the soft-inject provider with one item accepted in flight at the kill. `b2_16.sh` does the same on real Claude (run **S**).
  4. `reap.py` samples the process tree below my own server PID every 250 ms. It never matches by pattern. Several real runs ran at the same time, so each reap row below is attributed by PID and command, not by the whole tree.
- Mockups: `Legacy Node Room.dc.html` captured for 8 sub-states × {prompt, loop} × {`claude · soft-inject` (the default), `codex · queue only`} (`scripts/mockcap16.mjs`), plus the two static sheets. `pairs/pair-*.png` = mockup left, app right. Colour, font and radius follow S12 and are not compared.
- Evidence: `evidence/visual-qa-16/`: `data/` (JSON and analyser text output), `pairs/`, `shots/`, `scripts/` (drivers, batch scripts, analysers, `scripts/workflows/` the scratch workflows).

## Decisions (2026-10-01)

1. **VQ16-1:** major, and it will be fixed. This follows the earlier late-injection decision: a message must never stay `sent` if nobody knows whether it was delivered.
   - During restart recovery, any soft-injected entry that has no operator row in the transcript goes back to the front of the queue as `queued`.
   - The operator row lives in the durable transcript, so it is the proof of delivery that survives a restart. The in-memory ledger does not survive one.
   - The room then shows the entry in the restored `QUEUED · saved to server` band. If the node ends, terminal reconciliation lists it as `NEVER SENT`.
   - Entries that already have an operator row stay as they are.
2. **VQ16-2:** after a per-item `Send now`, focus follows the withdraw focus rule. It moves to the same control on the next queued item. If no item is left, it moves to the message field. It never falls to `<body>`, whether the user clicked or pressed `Enter`.
3. **VQ16-3:** the VQ12-1 continuity rule applies. The dock keeps the injected entry until its operator row has rendered in the transcript, not for a fixed single poll. No frame shows the item in neither place.
