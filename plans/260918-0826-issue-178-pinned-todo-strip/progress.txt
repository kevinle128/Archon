## Codebase Patterns

### Outset focus outline vs clipping ancestors (US-005)
- **Where**: `packages/web/src/experiments/console/components/ConsoleTodoStrip.tsx` (section `p-[4px]`), `ConsoleNodeRoom.tsx` region (`overflow-clip [overflow-clip-margin:4px]`)
- **Pattern**: a `focus-visible:outline-offset-2` control that is flush with an `overflow:hidden`/`auto`/`clip` ancestor gets its ring clipped; `overflow-clip-margin:Npx` widens the clip edge by N. When the element is ALSO flush with the browser viewport edge, NO ancestor fix can paint the ring — the component itself must inset content (section `p-[4px]` keeps bg/border/radius full-bleed while the button gains paint room on all four sides). Never "fix" this by flipping to `outline-offset:-2`.
- **Probe**: walk `el.parentElement` chain in `evaluate`, compare `getComputedStyle(node).overflow` + `overflowClipMargin` + rects vs `rect ± (offset+width)`; log first clipper whose box fails to contain the outline.

### Todo fold semantics (US-001, canonical for US-002+)
- **Where**: `packages/web/src/lib/todo-state.ts`, evidence: `@oh-my-pi/pi-coding-agent/src/tools/todo.ts` (bun global cache, read-only)
- **Pattern**: `projectTodoState(inputs: readonly unknown[])` returns `TodoPhase[]` (`{phase, items:[{content,status,blocker?}]}`). Working state KEEPS emptied phases internally (rm-emptied phases remain targetable and keep their position for lazy `append`); only the RETURNED value filters `items.length > 0` and maps to fresh objects.
- **Normalizing**: `normalizeInProgress` runs after every successful MUTATING op (init included — first pending auto-promotes to in_progress) but never after `view` or after a rejected call. Claude `{todos:[…]}` snapshots are never normalized (two in-progress stay as supplied).
- **Reject = retain prior state**; at top level rejected vs no-op is unobservable. Inside `{ops:[…]}`, ANY unresolvable/failed entry rejects the whole batch (stricter than separate-call equivalence — deliberate, per "any invalid entry rejects the ENTIRE batch").
- **Targeting truthiness** mirrors the provider: truthy `task` wins over `phase`, falsy `task:''` falls through to phase/all; done/drop/rm bare = ALL; block/unblock REQUIRE one truthy target.
- **init**: `list` present non-nullish wins over flat `items`; `list:[]` is a valid clear; flat `items:[]`/missing data rejects; each list entry needs string `phase` + non-empty all-string `items`; duplicate phase names/task contents reject.
- **block**: reason is whitespace-collapsed (`replace(/\s+/g,' ').trim() || undefined`); re-block updates reason incl. clearing when absent; only pending/in_progress/blocked targets change (never reopens completed/abandoned). `blocker` key is deleted, not left undefined.
- **Missing-op inference** (only when `op === undefined`): non-empty `list`→init; non-empty `items` + truthy string `phase`→append; bare non-empty `items`→init only when `phases.length===0` (emptied phases still count); else no-op. `op` present-but-unknown never infers.
- **Example**: see the "observed two-phase fold" test in `todo-state.test.ts` — init 12-item Research/Implement list, done/block/drop → `1/12` summary with `Map the message path` in_progress.

### Repo tooling quirks
- `git commit -m "$(cat <<'EOF' …)"` broke on a heredoc containing `[...]`/`{ops:…}` — use `git commit -F <file>` instead.
- lint-staged runs `eslint --fix --max-warnings 0` + prettier on staged `*.ts` — prettier MUST be clean pre-commit or the hook mutates files.
- `*.test.ts` files are eslint-ignored; production `*.ts` is strictTypeChecked (`explicit-function-return-type`, no non-null assertion).
- Test commands are package-isolated: `cd packages/web && bun test <path>`; never root `bun test`. `bun run type-check` inside `packages/web` is the TS gate.
- `bun:test`'s `expect(x).toEqual(y)` requires y's type assignable to x's — cast deep-copied snapshots as `typeof inputs`, not `unknown`.

### Widened buildAgentHistory callers (US-002 → US-004 handoff)
