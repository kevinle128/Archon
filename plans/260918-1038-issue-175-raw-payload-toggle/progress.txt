## Codebase Patterns

### Total-function defensive capture
- **Where**: `packages/web/src/lib/tool-presentation.ts:559` (`captureRawPayload`), `:573` (`safeRawName`), `:506` (`safePresentation` precedent)
- **Pattern**: Read attacker-controlled fields inside one `try`; on any throw return the documented deterministic fallback. Non-string-but-readable `name` coerces to `'generic'` (mirrors `typeof input.name === 'string' ? input.name : ''` at `:420`) — coerce the field, keep the readable rest.
- **Example**: `catch { return { name: 'generic', input: undefined, output: undefined }; }`

### Serializer fallback that cannot rethrow
- **Where**: `packages/web/src/lib/tool-presentation.ts:589` (`toolRawPayloadJson`)
- **Pattern**: Build `{ name, input, output }` literal then `JSON.stringify(v, null, 2)` — undefined keys are omitted, null kept, insertion order fixed. On throw, rebuild `{ name: safeRawName(payload), error: 'payload is not serializable' }` — plain strings only, so the fallback stringify structurally cannot throw. No replacer (would silently alter values).

### Test scaffolds in agent-history.test.ts
- **Where**: `packages/web/src/lib/agent-history.test.ts:44-67` (`toolRow` helper), `:18-42` (`textRow`/`statusRow`), `:69-85` (`event`)
- **Pattern**: `toolRow({id, seq, name, toolUseId, input?, output?, metadata?})` builds `NodeMessageRow`s; `metadata: {tool_phase: 'call'|'result'}` drives `projectToolTranscript` pairing by `toolUseId`. Card `input` comes from the call row, `output` from the result row, `name` from `call ?? result`.
- **Gotcha**: narrow item with `if (tool?.kind !== 'tool') throw ...` before reading `.presentation` — the union has no `presentation` on assistant/lifecycle items.

### Lint/format/test commands
- **Where**: repo root `package.json` scripts
- **Pattern**: `bun run type-check` (all packages + scripts tsconfig), `bun x eslint <files> --max-warnings 0`, `bun x prettier --check <files>`, `bun test <file>`. Test files (`**/*.test.ts`) are eslint-ignored — lint only production files. Pre-commit husky/lint-staged runs `eslint --fix` + `prettier --write` on staged files.

### Raw toggle contract (both ToolHistory renderers)
- **Where**: `packages/web/src/components/workflows/NodeRoom.tsx` (`ToolHistory`), `packages/web/src/experiments/console/components/inspect/ConsoleAgentHistoryList.tsx` (`ToolHistory`)
- **Pattern**: `rawOpen` useState + `rawPanelId = useId()`; body bar is `flex items-center` with facts in `span.min-w-0` and the Raw `<button>` pinned `ml-auto flex-none`. `aria-expanded` always present, `aria-controls` only while open; `<pre id={rawPanelId}>` renders `toolRawPayloadJson(presentation.rawPayload)` only while open — payload never enters the DOM closed.
- **Gotcha**: happy-dom tests find the button via `row.querySelector('button[aria-expanded]')` — `textContent === 'Raw'` breaks once the ` ▾` marker mounts. Panel lookup: `win.document.getElementById(aria-controls)` — `useId` values contain `:`/`«»` so CSS id selectors do not work.
- **Gotcha**: eslint has BOTH `non-nullable-type-assertion-style` (rejects `x as string`) and `no-non-null-assertion` (rejects `x!`) — narrow with `if (x === null) throw ...` instead.
- **Gotcha**: `closest()` on happy-dom elements returns happy-dom `Element` which does not type-match DOM-lib `Element & {open:boolean}` rows in `toBe(row)` — assert `closest(...)?.getAttribute('data-tool-id')` instead.

### Orphaned yaml fixture pattern
- **Where**: `packages/web/src/components/workflows/no-hitl-clarify-graph.test.ts`, `packages/workflows/src/__fixtures__/`
- **Pattern**: `.archon/workflows/defaults/*.yaml` is tracked product config, not a fixture store — deletions there break tests that read them. Small consumed topologies inline into the test; large verbatim node sets (backticks/markdown in prompts) go to `packages/workflows/src/__fixtures__/*.fixture.yaml` read via `join(import.meta.dir, '__fixtures__', ...)`. Loader tests that asserted a deleted file's own topology were re-scoped to fixture-shape guards.

### Playwright vs collapsed <details>
- **Where**: `e2e/ui/agent-tool-row-visual.spec.ts`, `workflow-run-hitl{,-room}.spec.ts`
- **Pattern**: `getByRole` queries the accessibility tree — descendants of a collapsed `<details>` are absent from it and return 0 matches. For closed-state assertions inside a collapsed row use a DOM locator (`row.locator('button[aria-expanded]')`); reserve `getByRole` for post-open assertions. Similarly `locator.getAttribute()` auto-waits for existence — check `.count()` first when the element legitimately may not be mounted (Raw `<pre>` closed-state).

### Console unlayered wildcard border
- **Where**: `packages/web/src/experiments/console/theme.css:142-146`
- **Pattern**: `.console-root * { border-color: var(--border) }` is UNLAYERED and beats every Tailwind (layered) border utility incl. hover/focus/open variants. State-driven borders inside `.console-root` need a scoped unlayered override (`details[data-tool-id] button[aria-expanded]:is(:hover,:focus-visible,[aria-expanded='true'])`); pseudo-states can't be expressed inline, unlike the static-inline workarounds used by StreamCard/ProjectRow/MessageItem.
