## Accepted gaps to record in `reports/acceptance.md`

- **Dock disclosure copy.** `STEERING_INTERRUPT_DISCLOSURE` (`packages/web/src/lib/steering-dock.ts:76-77`) reads "stopped after the last completed tool call · files already written stay written". A Codex stream-abort kills the subprocess mid-tool, so the in-flight command may be left partially applied. The copy is owned by the ratified design spine (`DESIGN.md`/`EXPERIENCE.md`) and Claude's `aborted_tools` end has the same semantics, so this story does not change it; record it as a known inaccuracy with a pointer for the design owner.
- **Resume-after-kill fallback.** The provider's cold `startThread` retry on `attempt > 0` (`provider.ts:1073-1075`) and its synchronous `resumeThread` fallback (`:1005-1018`) can run a redirect turn on a fresh thread with only a generic "⚠️ Could not resume" system row. Pre-existing for every resumed Codex turn; not made fail-loud here (see `plan.md` §Authority). Record the spike's `resumeAfterKillSuccesses` value beside it and recommend a follow-up issue if it is below 3/3 at any later re-run.
- **Stop/Send-now cycle bound.** Each cycle spawns a fresh `codex exec`; no per-node rate limit exists. Same characteristic as Claude (Story 2.3) on the same routes — accepted, not new.
