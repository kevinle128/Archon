## Codebase Patterns

### Grok diagnostic uses production argv builders
- **Where**: `packages/providers/src/grok/interrupt-resume-spike.ts`, `provider.ts` (`buildGrokArgs`, exported `buildSpawnCommand`)
- **Pattern**: Spike-only flags (`--no-auto-update`, `--session-id`) are appended after `buildGrokArgs()`; never maintain a parallel flag implementation. No barrel export of the spike.
- **Example**: `const { args } = buildGrokArgs(...); args.push('--no-auto-update'); if (sessionId) args.push('--session-id', sessionId);`

### Stop request vs termination trigger are separate
- **Where**: `runGrokTurn` in `interrupt-resume-spike.ts`
- **Pattern**: `requestStopImmediately` stamps operator Stop time; `terminateOn` defers the tree signal to a typed boundary (`spawn` | `first-stdout-event` | `first-event:<type>` | `pid-file`). Settlement budget is request→exit, not signal→exit alone.
- **Example**: Stop at listener registration + `terminateOn: { kind: 'first-stdout-event' }` for M sampling.

### Descendant liveness uses exact fingerprints, not names
- **Where**: `collectDescendantFingerprints` / `isFingerprintAlive`
- **Pattern**: Record `pid` + start-time before kill; re-check identity after parent exit; brief settle wait before declaring survival; never `pkill` by name.
- **Example**: macOS non-tool Stop at M reaps cleanly after ~150–500 ms settle; mid-tool slow_tool.sh child can still survive group SIGTERM (B7/B9 BLOCKED).

### Marker retention is boolean-only in reports
- **Where**: continuation checks in spike
- **Pattern**: Plant unique in-memory markers; assert presence on resume/fork continuations; reports emit booleans only — never marker values or model text.
