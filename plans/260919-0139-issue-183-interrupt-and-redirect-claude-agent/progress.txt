## Codebase Patterns

### Dock-removal focus fallback (US-004)
- **Where**: `packages/web/src/components/workflows/ComposerDock.tsx` (mirrored in `experiments/console/components/ConsoleComposerDock.tsx`); pane-side target in `NodeTranscriptPane.tsx`/`ConsoleNodeRoom.tsx` (`focusLastRow`); row marker in `NodeRoom.tsx`/`ConsoleAgentHistoryList.tsx` (`data-last-row` + `tabIndex={-1}` on the last rendered item only).
- **Pattern**: when a removable control region can own focus, latch `focusInsideRef` on `focusCapture` (cleared on blurCapture leaving the region) and track `controlsMountedRef` across mode transitions. On the mounted→unmounted transition (or full unmount while focus was inside), call an injected `focusLastRow()` that focuses `[data-last-row]` else the transcript scroller with `preventScroll` — never let focus fall to `<body>`. The latch is what makes React 19 StrictMode mount replay safe: cleanup fires on a dock that never owned focus and must not steal it.
- **Test seam**: pane/room tests drive the fallback by flipping `runStatus`/`isLive` live→terminal with focus inside the dock — no network needed. The polling/isolation tests are timing-bound under this host's ~100 load; treat 5s per-test timeouts as environmental and re-run (see US-004 learnings).

### Cross-worktree shared stash list (US-003 hazard)
- **Where**: `git stash` — the stash list is repo-wide, shared across ALL worktrees of this checkout.
- **Pattern**: NEVER bare `git stash pop` here. Another ralph worktree (e.g. `archon/thread-5da49924` holding `ralph-unblock:US-004`) can push a stash between your `git stash push` and `pop` — bare pop then applies THEIR stash and conflicts. Always `git stash list` first and `git stash pop stash@{N}` with the exact index of your `ralph-unblock:<story>` entry; leave foreign entries untouched. lint-staged also briefly creates its own backup stash during commits.
- **Recovery**: if a wrong stash was applied, `git reset --hard HEAD` (nothing of yours is in the tree — it's still stashed), then pop by exact index.

### Dev server port in a worktree (US-003)
- **Where**: `packages/core/src/utils/port-allocation.ts` (`getPort`)
- **Pattern**: `PORT` env wins; else worktree path → deterministic `3090 + hash-offset` (3190–4089); else 3090. BUT `bun --filter @archon/server dev` runs with cwd=`packages/server`, so worktree detection fails and it falls back to 3090 — set `PORT` explicitly when generating types from a worktree (e.g. `PORT=4038 bun run dev:server`), then `bun x openapi-typescript http://localhost:<port>/api/openapi.json -o packages/web/src/lib/api.generated.d.ts`. Verify any already-listening port's owner worktree via `lsof -p <pid> | grep cwd` before reuse — a server on 3090 may belong to a different checkout.

### Claude interrupt seam (US-001)
- **Where**: `packages/providers/src/claude/provider.ts` (`singleTurnInput`, `raceInterruptFailure`, `sendQuery`)
- **Pattern**: interrupt-capable calls send `prompt` as a one-message `AsyncIterable<SDKUserMessage>` held open by a provider-owned deferred (`releaseInput`). `interruptSignal` abort → bound `query.interrupt()` exactly once — never `controller.abort()`/`query.close()` (those remain `abortSignal`'s Cancel teardown). An abort landing before the query binds sets `interruptRequested`, flushed right after `currentInterrupt` is assigned.
- **Gotchas proven against SDK 0.3.209** (`reports/claude-interrupt-resume-spike.md`):
  - `await stream.interrupt()` inside `for await` DEADLOCKS — the ack is serviced by the same stream pump; fire unawaited.
  - Held-open input keeps the stream open AFTER the terminal result — resolve the input gate when the result chunk is observed, or the subprocess never exits.
  - Real SDK yields the abort-marked result (`terminal_reason='aborted_streaming'`, `subtype='error_during_execution'`, `is_error=true`) AND THEN throws `Claude Code returned an error result: [ede_diagnostic] result_type=user` — consumers see result chunk + trailing throw; executor must classify on the result it already saw.
  - `Query.interrupt()` exists only on streaming-input queries; string prompts expose no `interrupt()`.
- **Iterator pitfall**: `iterator.return()` awaited while the inner iterator is parked at a pending `next()` queues behind that read and never resolves — skip `return()` in the read-failed path and keep abandoned `next()` promises observed with `.catch(() => undefined)`.

### Environmental flakes (this worktree)
- `bun test src/community/omp/session-usage.test.ts` — 'oversized line omits all hidden enrichment' times out at the 5s default on the external WD_BLACK drive; passes with `--timeout 30000`. Pre-existing, unrelated to provider capabilities.
- Root `bun run type-check` fails on PRE-EXISTING `@archon/web` error: `src/experiments/console/components/ConsoleNodeRoom.test.tsx(2966,7)` — `execution?: ... | undefined` vs required `execution: ... | null`. packages/web does not depend on @archon/providers; untouched by US-001. Package-scoped `type-check` in packages/providers is clean.

### Steering handle turn lifecycle (US-002)
- **Where**: `packages/workflows/src/steering-registry.ts` (`NodeSteeringHandle`), executor integration in `dag-executor.ts` (~line 3196 direct register, ~5960 loop register).
- **Pattern**: one ACTIVE turn per handle, tokenized by `beginTurn(controller)` immediately before each `sendQuery`. `endTurnStream(token)` in the stream `finally` clears ONLY the matching controller (a late `interrupt()` then waits on classification instead of aborting a dead stream). `settleTurn(token, outcome)` is classification's write — resolves that token's shared pending interrupt once. `enterIdle(token)` settles as `idle-after-interrupt` and returns ONE waiter for `send_now`/`terminated`. Server route (US-003) calls `interrupt()` → shared promise resolves to the classified outcome; `accept(msg, 'queue'|'send_now')` is the ONLY route-side mutation.
- **Gotchas**:
  - `wasOperatorInterrupted(token)` gates ALL interrupt classification — a natural `terminalReason`-less result that raced a Stop stays natural (settles `generating` or `node_finished` at the boundary); the flag only reclassifies abort-marked ends (`aborted_streaming|aborted_tools`) and abort-shaped throws.
  - Interrupt resume id = `newSessionId ?? turnResumeId` (direct) / `settledTurnSessionId ?? currentSessionId` (loop) — a throw can interrupt before any result chunk, and a loop re-ask's throwaway session is never a redirect target.
  - The 'interrupted' transcript status row is AWAITED before `enterIdle` — the interrupt request only resolves once the committed outcome exists (agent-history fold overrides the preceding tool card).
  - `raceIdleWake` polls `getWorkflowRunStatus` with `CANCEL_CHECK_INTERVAL_MS` but its FIRST tick is immediate — idle tests can't wait 10s, and a pre-terminal run must not linger.
  - `interrupt()` while already idle resolves `idle-after-interrupt` immediately (idempotent Stop); `send_now` while generating queues like a normal enqueue — no wake.
  - Mock-store `getWorkflowRunStatus` reads a captured flag — flip it inside the generator to simulate mid-stream cancel (first chunk always polls; throttle map starts at 0).
