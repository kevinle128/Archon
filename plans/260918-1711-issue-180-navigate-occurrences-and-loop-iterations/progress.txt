## Codebase Patterns

### Occurrence navigator + focus redirect
- **Where**: `NodeTranscriptPane.tsx` / `ConsoleNodeRoom.tsx` (controls row after the scroller), `room-scroll-follow.ts` (`jumpToOccurrence`).
- **Pattern**: bottom row `[navigator, jumpButton]` in `justify-between`. Select commits on `change` only; `navTarget` holds the last committed `occurrence_id`, and the displayed value derives to `''` (placeholder) whenever the target leaves the displayed-group list. A deps-free effect watches `navigatedHeadingRef`: when that heading disconnects AND focus dropped (`activeElement` ∈ {null, body, detached heading}), focus lands on the select if still mounted else the scroller — never body. Scroller needs `tabIndex={-1}` to be a programmatic target. Heading focus uses `focus({preventScroll:true})` so the reducer stays the single scroll writer.
- **happy-dom test recipe**: per-element `getBoundingClientRect` stubs drive the fully-visible check; `Object.defineProperty(el,'scrollHeight'|'clientHeight')` for viewport math; commit a select via `el.value = v; dispatchEvent(new win.Event('change',{bubbles:true}))`; assert focus with `win.document.activeElement as unknown as Element | null`.

### Dated decision recording convention
- **Where**: `ARCHITECTURE-SPINE.md` (AD amendments), `EXPERIENCE.md` (`adopted delta N, YYYY-MM-DD`), `DESIGN.md` (same delta scheme — last used was delta 4, so new records are delta 5+).
- **Pattern**: gate decisions are recorded as dated amendments inside the owning canonical artifact (never only in `plan.md`); the plan then indexes into them. Amendments state consequences explicitly so no implementer re-derives them.

### Execution/occurrence label vocabulary
- **Where**: `packages/web/src/components/workflows/build-log-rows.ts:94-103` (and its Console twin).
- **Pattern**: `baseName ×N` for loop-ancestry iteration, `baseName #N` for `route_activation_seq`. The B4 rule reuses `#N` inside occurrence headings; `·` separates facts; `›` joins an ancestry path; `Attempt`, `Pass`, reason-only labels, raw UUIDs are all forbidden.

### Scroll-follow is a pure reducer
- **Where**: `packages/web/src/lib/room-scroll-follow.ts` (`createScrollFollow` / `onRoomScroll` / `jumpToLatest`), used identically by `NodeTranscriptPane.tsx` and `ConsoleNodeRoom.tsx`.
- **Pattern**: `{follow, scrollTop, pinToBottom}`; a reader scroll >24px from bottom flips to manual hold. New navigation interactions must be explicit transitions on this reducer (e.g. `jumpToOccurrence` → manual-hold), never `ignoreNextScroll`-style event suppression.

### Two controls beside the transcript, different kinds
- **Pattern**: `Execution` (header `<select aria-label="Execution">`, `NodeRoomHeader.tsx:64` / `ConsoleRoomHeader.tsx:60`) **filters** — it changes which messages load. The Story 1.7 `Jump to` navigator **scrolls** — it moves within loaded messages and issues no request. They are deliberately separate controls; never merge them.

### Room structure for scroll controls
- **Where**: `NodeTranscriptPane.tsx:406-428`, `ConsoleNodeRoom.tsx:891-905`.
- **Pattern**: `RoomRegion > [TodoStrip?] > overflow-y-auto scroller > bottom row`. The `Jump to latest` button renders conditionally (`!follow.follow && running|awaiting`) as a sibling after the scroller — the navigator control row takes the same sibling position.

### In-room heading convention
- **Where**: `TodoStrip.tsx:162`, `NodePalette.tsx:37`.
- **Pattern**: room title is `h2`; in-room sub-section labels are `h3` uppercase text-secondary — occurrence headers adopt `h3` and `tabindex="-1"` (programmatic focus only, not a `Tab` stop).

### Branch reality: `develop`, not `dev`
- **Pattern**: `origin/HEAD` = `develop`; `origin/dev` is deleted; local `dev` is stale (~68 behind). AGENTS.md, e2e-smoke.yml, release.yml were corrected 2026-09-19. `.claude/skills/release/SKILL.md` still encodes `dev`→`main` (residual debt, release-time fix — also touched by PR #202).

### Derive wire types from api.generated.d.ts, never re-declare
- **Where**: `packages/web/src/lib/agent-history.ts` (`TranscriptExecution`), `occurrence-groups.ts`.
- **Pattern**: `type TranscriptExecution = NonNullable<NonNullable<NodeMessageRow['metadata']>['execution']>` — indexed access off the generated row type keeps the render-neutral contract in lockstep with the wire. Hand-copied interfaces drift; derived types make drift a compile error.

### Occurrence grouping is render-neutral
- **Where**: `packages/web/src/lib/occurrence-groups.ts`.
- **Pattern**: `groupOccurrences(items)` returns `{prefixItems, groups, showHeaders}` — grouping is a pure lib function over `AgentHistoryItem[]` keyed by `execution.occurrence_id`. Unkeyed items before the first keyed row go to `prefixItems`; unkeyed items after join the nearest preceding group; a repeated non-contiguous key rejoins its original group. `showHeaders = groups.length >= 2`. Shells call this and render headings — they never derive labels themselves.

### Stream correlation keys must carry execution identity
- **Where**: `packages/web/src/lib/project-text-transcript.ts` (keyed `stream_id\0message_id\0block_id\0occurrence_id\0attempt_id`), mirrors `pair-tool-transcript.ts`.
- **Pattern**: providers reuse stream/message/block ids across occurrences and attempts — identity keys without occurrence+attempt silently concatenate text across runs. Anonymous deltas track the same identity and reset the accumulator when it changes.

### Adding a required field to AgentHistoryItem
- **Where**: `packages/web/src/lib/agent-history.ts` + `NodeRoom.test.tsx` helpers.
- **Pattern**: only `NodeRoom.test.tsx` constructs `AgentHistoryItem` literals directly — all other suites go through `buildAgentHistory()` and compile untouched. Update the three literal helpers (`execution: null`) and whole-item `toEqual` assertions; everything else follows the builder.

### Displayable occurrence groups are filtered at the shell, not in the lib
- **Where**: `ConsoleNodeRoom.tsx` (~line 650), `ConsoleExecutionHistory.tsx` (~line 213), `ConsoleAgentHistoryList.tsx` (`historyItemRowVisible`).
- **Pattern**: `groupByOccurrence` stays render-neutral — shells post-filter `groups` to *displayable* ones and rebuild `{prefixItems, groups, showHeaders}` before passing `occurrenceGrouping` down. Console rule: a group is displayable iff some row passes `historyItemRowVisible(item, {showToolCalls, showSystem})` OR a hidden tool row owns an anchored Ask (`anchoredAskToolIds`); `ConsoleExecutionHistory` uses the visible-row rule only (extras are unanchored `renderAtEnd`). `showHeaders` recomputes as `displayableGroups.length >= 2`, so filtering to one group removes headings. **US-004 navigator options must derive from this same displayable list, never raw groups.**
- **Heading target contract**: `h3 id={`${useIdPrefix}occ-${group.key}`}` + `tabIndex={-1}` in both shells — the navigator anchors/focuses these ids.
